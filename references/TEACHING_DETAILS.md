# Teaching Details — 分语言教学规范与输出模板

本文件在需要更高精度或代码跨语言时按需读取。

## 统一的每轮输出框架

1. **本段定位**：`文件 / 模块 / 原行号 / S 编号 / 触发时机`。
2. **原代码**：本段未经删节的全部原文，必要时提供行号旁注而不是篡改代码。
3. **逐行解释**：每一行标明**执行时机 → 语法 → 实际动作 → 修改了什么状态 → 为什么需要**。
4. **输入输出契约**：参数名、类型、形状、前置条件；返回值与副作用；涉及指针则写内存区域与生命周期。
5. **执行追踪（重点）**：通过时间线或状态表按运行顺序列出实际执行语句、当前值、下一步和函数返回；`if` 明确分支，`for` 明确迭代次数与退出。
6. **上游/下游**：当前状态由谁产生，变化影响谁；指出哪些调用从源码可证实，哪些只是典型架构。
7. **一个阅读理解检查点**：预测下一行、变量变化或状态迁移；不安排手写代码。等待答题或顺应用户直接继续。
8. **进度**：本轮刚完成部分、未讲解部分、需核对的外部实现。

## 教学目标与“不写代码”约束

- 完成标志是**能顺着真实源码解释输入如何流到输出**，并看懂主要分支、内存/状态变化与模块协作。
- 默认任务为“读懂这段”“下一步会执行什么”“某变量为何变化”，而不是“自己实现这一段”。
- 语法属于阅读辅助：遇到不懂的语法解释该语句的实际作用，不脱离源码进行冗长语言教程。
- 长代码第一次讲解优先展示完整调用图与执行大纲，让用户知道从何处开始读；代码位置与执行时间位置须严格区分。

## Python 系统源码的检查点

- 识别类属性、实例属性、方法、静态/类方法、装饰器、运算符重载及对象生成时刻。
- 对每个参数解释默认值生命周期；可变默认对象尤其需注意复用。
- 区分 `copy`（浅拷贝）、直接赋值（引用）、列表切片（产生新列表）及实际张量 view/copy 行为。
- 分析 `__getstate__`、`__setstate__`、`__len__`、`__getitem__` 的运行条件和结果。
- 保留变量不变量。例如 `num_prompt_tokens` 是初始长度，`num_tokens` 可随 `append_token` 增长。
- 如果需要表示异步或多进程状态，注明同名对象可能不是同一份内存。

## vLLM/推理 Infra 专项清单

必须先判断代码是否真实包含这些概念，不能套模板硬加：

- **请求维度**：`seq_id`、prompt token、completion token、status、sampling params。
- **调度维度**：waiting/running、admission、prefill/decode、抢占、重新计算/恢复。
- **缓存维度**：`num_cached_tokens`、逻辑/物理 Block、block table、prefix cache、KV tensor。
- **执行维度**：model runner、attention、sampling、last token、prefill/decode input preparation。
- **边界**：`num_tokens` 不自动代表所有 token 的 KV 都已缓存；`block_table` 不等于 Tensor；一个 sequence 对象未必自己管理显存；方法定义不等于调度真正发生。
- **时序**：严格区分“Model 输出 token 之后”“下轮 decode 之前”“新 token 已进入 KV Cache 之后”。

## CUDA/Triton 专项清单

- 提前画出 `gridDim/blockDim/threadIdx/blockIdx` 或 `program_id` 与逻辑输出元素的映射。
- 对每个 load/store 描述地址公式、stride、valid mask、越界保护、数据类型、对齐条件。
- 对 shared memory、寄存器、全局显存的使用和同步点做生命周期推演。
- 归约/scan 等算法说明数学不变量、边界样本和并行结构，不把性能优化与数值等价混为一谈。
- Triton 转 CUDA 的解释要标注：**仅用于理解逻辑，不能直接推断实际编译后的线程布局和性能**。
- 对融合类优化精确列出融合前有哪些 kernel/算子、融合后省掉哪些中间张量/launch/访存。
- 性能论断要以 Nsight Systems、Nsight Compute、benchmark 等对应证据支撑；无数据时只列可能收益。

## C/C++/编译器源码专项清单

- 标明数据结构内存所有权、引用/指针生命周期、异常或错误处理路径。
- 对模板、宏、类继承、虚函数、回调、IR Pass 说明编译期/运行期差别。
- MLIR 等 IR 要分开解释 Operation/Region/Block/SSA，以及 Pass 触发的 rewrite/lowering 时刻。
- 对数值/科学计算代码解释维度、数学表达、稳定性前提与输入输出规范，不臆测 library contract。

## 回答长度与交互节奏

默认：
- 首轮：完整全局图 + 覆盖表 + 第一段深入解释（用户已有全局图则略过重复部分）。
- 后续轮：**一个连续逻辑段** + 完整该段源码 + 精读 + 手算验证 + 一个小问题。
- 用户明确说“继续”时：承接上一位置，避免复述上一轮主体内容。
- 用户明确说“所有代码一次讲完”时：按编号连续覆盖所有行；若无法全部输出，如实标明剩余的编号/行号。
- 用户说“只给结论”时：不强制互动、不添加额外课程内容。
